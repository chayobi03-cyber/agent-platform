# APF Living Specification Governance

## Change rule
Specification changes must identify the triggering finding/asset/test and record the resulting decision. Unverified hypotheses must not silently become normative requirements.

## Asset lifecycle
DISCOVERED → CANDIDATE → VALIDATING → VALIDATED → ARCHITECTURE_ADOPTED

Possible outcomes: REVISED, DEPRECATED, INVALIDATED, REJECTED.

## Session close protocol
Every APF research session should record:
- New findings
- New/updated assets
- Claims changed
- Evidence added
- Hypotheses falsified
- Decisions made
- Specification changes
- Open questions
- Next experiments

## Traceability
Preferred chain:
Research Finding → Asset → Claim → Specification → Test → Evidence → Decision.

## Architecture freeze rule
No Core Invariant is permanent until it survives heterogeneous workload tests and explicit counterexamples.
