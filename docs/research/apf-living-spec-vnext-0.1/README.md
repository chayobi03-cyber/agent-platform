# APF Living Specification vNext 0.1

Purpose: maintain APF as a living, evidence-linked specification rather than a frozen architecture document.

## Structure
- SPEC.md — scope, positioning, candidate core contracts
- ASSETS.md — Research/Architecture/Verification asset registry
- CLAIMS.md — architecture claims and status
- FALSIFICATION.md — falsification benchmark and failure conditions
- LANDSCAPE.md — external capability mapping and ownership boundary
- GOVERNANCE.md — asset/spec lifecycle and session update protocol
- STATUS.yaml — current maturity and open work

## Operating principle
Research findings do not become requirements automatically. A claim must accumulate evidence, survive explicit counterexamples/tests, and receive an adoption decision before becoming normative architecture.

## Current hypothesis
APF should be evaluated as a domain-independent work-execution model that can integrate mature Agent, Workflow, Durability, Provenance, Observability, Validation, and Human-decision capabilities without reimplementing them.

The strongest current differentiation candidate is a verification-driven asset lifecycle: validated execution knowledge becomes reusable, revalidated, revisable, or rejectable engineering knowledge.
