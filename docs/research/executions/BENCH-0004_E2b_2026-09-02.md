## 1. Why E2b exists

BENCH-0004-E2 is blocked at G1: its fixture bytes were never in this repository. That was
verified rather than assumed — no commit on any branch, no stash, and neither of the two
dangling objects (both compiled bytecode of this session's own scripts) matches a locked hash.
The repository's first commit predates the E2 fixture lock, and the fixture was built outside
this repository entirely. **Git rollback cannot recover it.**

E2b answers the same scientific question over a corpus that is present and verifiable.

**E2b is not E2.** Its hashes are its own and must never be compared against the E2 lock. If the
original bundle later arrives, E2 should be run separately; two independent results on the same
question would be stronger evidence than either alone.

## 3. Design

Twelve engineering-history questions, frozen with declared gold evidence in
`tools/bench0004_e2b/cases.json` **before** any context was built or scored. Eight T/R/P cells x
12 cases = 96 contexts.

- **T** — retrieval restricted to the version current as of the question's reference date; the
  context carries version currency.
- **R** — one-hop expansion along declared corpus relations.
- **P** — provenance-aware context: commit, date, author, path.

All three sit on top of one shared TF-IDF cosine retriever. The mechanisms act on the retriever,
never inside it.

Scoring: fraction of declared gold evidence present in a form that can answer the question. Where
a case is declared temporally dependent, a stale version earns no credit; where it is declared
provenance-dependent, unattributed evidence earns no credit. Those requirements were declared in
the case file in advance, not inferred from results.

## 5. Stage 1 result — context sufficiency

Case-blocked OLS, `context_score ~ C(case) + T*R*P`, n=96, R² = 0.7383, case block p = 4.6e-15.

| Term | E2b coefficient | E2b p | Original E2 coefficient | Original E2 p |
|---|---:|---:|---:|---:|
| T | +0.0191 | **0.438** | +0.1683 | 0.023 |
| R | +0.0990 | 0.0001 | +0.1675 | 0.024 |
| P | +0.1406 | <0.0001 | +0.2433 | 0.001 |
| T×R | −0.0191 | 0.438 | — | 0.867 |
| T×P | +0.0156 | 0.526 | — | 0.867 |
| R×P | +0.0260 | 0.291 | — | 0.663 |
| T×R×P | +0.0052 | 0.832 | — | 0.822 |

Cell means: T0R0P0 0.2639 · T0R0P1 0.4722 · T0R1P0 0.4583 · T0R1P1 0.7500 · T1R0P0 0.3195 ·
T1R0P1 0.5695 · T1R1P0 0.4167 · T1R1P1 0.7917. Grand mean 0.5052.

### What replicated

**P and R replicate.** Both are significant, both in the same direction, and P remains the
largest main effect — the same ranking the original factorial reported. The absence of any
significant interaction also replicates.

### What did not

**T did not replicate.** The original reported +0.1683 at p=0.023; E2b finds +0.0191 at
p=0.438 — indistinguishable from zero.

This meets the falsifier stated for `CLM-0004a`: *"temporal filtering produces no measurable
context-sufficiency gain after case blocking."*

### Was T given a fair test?

Yes, on the evidence available. Temporal filtering **changed the retrieved set in 44 of 48
comparisons (92%)**, and did so in all eight cases declared temporally dependent. T was not
inert — it changed what was retrieved and those changes did not improve evidence sufficiency.

This is the same shape as the R1 finding, one level down: R1 found that added structure changed
*which document* ranked first without improving recall; E2b finds temporal filtering changes
*which version* is retrieved without improving sufficiency.

**Bounding limitation.** Ten of the sixteen corpus paths have only one committed version. For
those, temporal filtering has nothing to choose between, so the corpus's version depth caps how
much sufficiency T could add. The null is real but its scope is bounded by that depth; a corpus
with deeper revision history could produce a different result.

## 8. Anti-bias note

The result above is reported as measured. E2b was built by the same session that then analysed
it, which is a real bias risk; the mitigations were declaring the case set and its scoring
requirements before building any context, pinning the corpus, and making the build deterministic
so any reviewer can reproduce the bytes and recompute the result. The finding that most
disconfirms the session's own prior work — T failing to replicate — is reported first and
unqualified.
