# BENCH-0004 Round 2 — Cross-document Temporal Reasoning Attack

**Date:** 2026-08-31
**Status:** Executed / pilot empirical result
**Target claim:** CLM-0004 — Temporal/provenance-aware history improves engineering retrieval

## 1. Attack objective

Round 1 showed no document-level recall gain for D over C. Round 2 therefore attacks the remaining narrower proposition:

> Relationship/temporal/provenance-aware retrieval improves answer grounding or decision utility on engineering questions whose answer depends on cross-document history, version transitions, or causal relations, even when document-level recall is unchanged.

The attack uses only repository-preserved APF material and Git commit provenance available in the repository. It is not an independent engineering corpus.

## 2. Frozen corpus

Seven repository documents / evidence objects were frozen:

1. `CONSTITUTION.md`
2. `docs/governance/LESSONS_LEARNED_2026-08-30-engineering-work-mvp.md`
3. `docs/research/CLAIM_INVENTORY.md`
4. `docs/research/P0_BENCHMARK_CASES_v0.1.md`
5. `docs/research/RESEARCH_CORPUS_MAP.md`
6. `docs/research/CLAIM_RECONCILIATION.md`
7. `docs/research/executions/BENCH-0004_RUN_2026-08-31.md`

Git commit metadata was additionally used as temporal provenance for the foundation → constitution → cold review → benchmark operationalization → pilot sequence.

## 3. Conditions

### C — semantic baseline

TF-IDF cosine similarity over the frozen corpus, representing a competent lexical/semantic document retriever.

### D — relationship/temporal-aware prototype

C plus fixed, corpus-derived entity/relationship propagation and temporal weighting. The relationship graph is explicitly derived from declared repository relations (claim↔benchmark, lesson↔claim, benchmark↔execution, constitution↔reconciliation, corpus↔reconciliation). No ground-truth labels are used in scoring.

This is an interpretable prototype, not a production graph/vector retrieval implementation.

## 4. Cross-document task set

Eight questions were frozen before scoring. Each requires evidence from at least two repository objects; most require three.

| ID | Cross-document question | Required evidence |
|---|---|---|
| R2Q1 | What claim was narrowed before benchmarking, what benchmark tests it, and what did the first execution conclude? | CLAIM + BENCHMARK + EXECUTION |
| R2Q2 | What research lesson motivated CLM-0004, and where was it converted into a falsifiable benchmark? | LESSONS + CLAIM + BENCHMARK |
| R2Q3 | What is the governance path from a research finding to an architecture candidate, and where is the benchmark execution gate? | RECONCILIATION + BENCHMARK |
| R2Q4 | Why was the first retrieval pilot insufficient to settle CLM-0004, and what exact second-round task class was proposed? | EXECUTION + BENCHMARK |
| R2Q5 | What changed from the initial APF foundation to the constitution, and why does that matter for interpreting commits versus decisions? | CONSTITUTION + RECONCILIATION |
| R2Q6 | How does the corpus map constrain benchmark execution, and what must happen before the research corpus is considered complete? | CORPUS + RECONCILIATION |
| R2Q7 | Which engineering-history concepts are claimed to be useful, and which one has already failed to show recall improvement in the first ablation? | LESSONS + CLAIM + EXECUTION |
| R2Q8 | What is the difference between a negative benchmark result and an architecture decision in APF's governance model? | EXECUTION + CONSTITUTION + RECONCILIATION |

## 5. Scoring

Primary metric: **cross-document chain coverage@k** = fraction of required evidence objects present in the top-k retrieved set.

Secondary binary metric: **complete chain@k** = all required evidence objects present in the top-k set.

This is deliberately stricter than Round 1 document recall: finding one relevant document is insufficient when the answer depends on a historical chain.

## 7. Direct attack result

D outperformed C on the primary cross-document chain metric at both k=2 and k=3.

The strongest improvement occurred on questions requiring explicit governance/benchmark/execution linkage (R2Q3–R2Q5). D also improved R2Q7 at k=2.

However, D did not dominate universally. R2Q8 lost one required evidence object at k=3, and R2Q1 showed no gain. Therefore the result is evidence of **conditional utility**, not universal superiority.

## 8. Falsification assessment

### Broad CLM-0004

**State: WEAKENED / INCONCLUSIVE — not promoted.**

Round 1 already showed that adding structure does not guarantee document-level recall improvement. Round 2 shows a meaningful advantage on deliberately cross-document historical questions, but the corpus is small and APF-dogfood-heavy.

### Narrow subclaim supported by this run

> Relationship/temporal-aware retrieval can improve recovery of multi-document engineering evidence chains when the task explicitly requires history, governance transitions, or linked claim→benchmark→execution reasoning.

**Provisional state: SUPPORTED within this pilot scope.**

## 9. Important limitations / attack integrity

1. The corpus is not independent of APF development.
2. The D graph/boost mechanism is hand-specified and therefore not evidence for a production architecture.
3. Ground truth is repository-object level, not expert answer-level judgment.
4. No LLM answer generation was used; unsupported-claim rate and answer utility remain unmeasured.
5. The task set is n=8.
6. Provenance, temporal, and relationship effects are not fully separated from one another in this round.
7. The result demonstrates retrieval-chain coverage, not end-user engineering productivity.

## 10. Required next attack

To try to falsify the surviving narrow claim, create an independent engineering corpus containing real revision/configuration/evidence transitions and compare:

- C: semantic + metadata retrieval
- D1: temporal-only
- D2: relationship-only
- D3: provenance-only
- D4: combined temporal + relationship + provenance

Score answer-level evidence grounding, temporal-order accuracy, chain completeness, unsupported-claim rate, expert utility, and retrieval latency.

If D4 loses its advantage under this controlled decomposition, split CLM-0004 into narrower mechanism claims rather than preserving the broad statement.

## 11. Verdict

**Round 2 does not falsify the narrow cross-document reasoning proposition. It weakens the broad universal retrieval claim and provides the first positive evidence that structured temporal/relationship retrieval may have value specifically for multi-document engineering-history reconstruction.**
