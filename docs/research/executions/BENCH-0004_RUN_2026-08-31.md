# BENCH-0004 Retrieval Ablation — Execution 2026-08-31

## Status

**Pilot execution / empirical result recorded**

This is the first executable BENCH-0004 pilot against the current APF research corpus. It is not yet an independent replication and must not be treated as final architectural evidence.

## Claim under attack

**CLM-0004 — Temporal/provenance-aware history improves engineering retrieval**

Working claim: retrieval that understands chronology, provenance, configuration, and relationships recovers useful engineering reasoning better than flat semantic retrieval alone for target engineering questions.

## Predeclared falsifier

D does not outperform C on declared engineering tasks, or any apparent improvement disappears after controlling for indexing/metadata quality.

## Corpus

Frozen corpus for this pilot:

1. `docs/research/CLAIM_INVENTORY.md`
2. `docs/research/P0_BENCHMARK_CASES_v0.1.md`
3. `docs/governance/LESSONS_LEARNED_2026-08-30-engineering-work-mvp.md`
4. `docs/research/RESEARCH_CORPUS_MAP.md`

The corpus is intentionally small and APF-dogfood-heavy. This is a limitation and an explicit source of possible bias.

## Conditions

- **B:** lexical TF-IDF/LSA semantic-style retrieval baseline.
- **C:** B plus lightweight metadata-aware boosting.
- **D:** C plus explicit relationship/temporal/provenance intent rules.

Important: D is an interpretable prototype of relationship/temporal/provenance reasoning, not a production graph/vector retrieval implementation. Therefore this run can challenge the claim but cannot establish the superiority of a mature D implementation.

## Task population

10 frozen questions covering:

- claim/falsifier lookup
- retrieval-condition lookup
- temporal/relationship retrieval rationale
- C-vs-D control definition
- retrieval metrics
- evidence vs AI inference
- engineering-history chain
- corpus governance
- counter-evidence/falsification criteria
- graph-vs-product-objective distinction

Ground truth was defined as the document(s) containing the information required to answer each question.

## Aggregate result

Top-1 evidence-document hit rate:

- B: **9/10 = 90%**
- C: **9/10 = 90%**
- D: **9/10 = 90%**

Top-2 evidence-document hit rate:

- B: **10/10 = 100%**
- C: **10/10 = 100%**
- D: **10/10 = 100%**

Therefore D showed **no recall advantage over C** on this pilot.

## Direct attack on CLM-0004

The required comparison is C vs D. On the frozen task set:

```text
C recall = 90% top-1
D recall = 90% top-1

C top-2 recall = 100%
D top-2 recall = 100%
```

The relationship/temporal/provenance layer did not produce a measurable recall improvement.

This is a **negative result against the current broad form of CLM-0004**.

## Counter-observation

D changed *which* evidence document was ranked first for some questions, but those changes did not improve the declared recall metric. In particular, D improved Q5's ranking from `CORPUS_MAP` to `BENCHMARK_CASES`, but Q5's ground-truth set already included `BENCHMARK_CASES` in the top-2 baseline, so the change did not create a recall gain.

## Interpretation

Current result state: **WEAKENED / INCONCLUSIVE**, not FALSIFIED.

Reasons:

1. The task set is small (n=10).
2. The corpus is APF dogfood data rather than an independent engineering corpus.
3. D is a lightweight rule-based prototype rather than a full relationship-aware retrieval system.
4. Ground truth is document-level rather than answer-span/expert-judgment based.
5. No human answer-utility or unsupported-claim measurement was performed.
6. No latency or indexing-quality normalization was performed.

## What this run successfully falsifies

It falsifies the weaker implicit proposition:

> Simply adding explicit temporal/relationship/provenance routing to an already competent semantic+metadata retriever guarantees measurable retrieval-recall improvement.

That proposition is **not supported by this run**.

## What remains open

A narrower claim remains testable:

> Relationship/temporal/provenance-aware retrieval improves answer grounding or decision utility on engineering questions whose answer depends on cross-document history, version transitions, or causal relations, even when document-level recall is unchanged.

This requires a harder benchmark with answer-level scoring and deliberately cross-document temporal/version questions.

## Next falsification move

Do **not** promote CLM-0004.

Run a second BENCH-0004 task set containing questions where the answer cannot be recovered from a single document, for example:

- Which revision introduced the failed validation result, and what decision followed it?
- Which configuration was active when the evidence was produced?
- Which rejected hypothesis explains why the later design change occurred?
- What changed between two engineering states and which evidence supports the transition?

Score:

- answer-level evidence grounding
- unsupported-claim rate
- cross-document chain completeness
- temporal-order accuracy
- expert-rated answer utility

If D still does not beat C, CLM-0004 should be **rejected or split into narrower mechanisms**.
